## Context

The clawone microvm on dapperehaan already runs one OpenClaw gateway instance for Pim. OpenClaw is installed via npm at first boot and configured via the `onboard` wizard. The config and auth tokens persist in `/var/lib/openclaw/` on the microvm's persistent volume. The gateway runs as systemd service `openclaw-gateway` under system user `openclaw`.

## Goals / Non-Goals

**Goals:**
- Second OpenClaw instance for Janine on port 18790
- Completely separate identity, config, state, and Matrix bot
- Dutch-language assistant personality
- Easy CLI access to both instances via wrapper scripts
- Fix pimsnel.com hostname typo in existing specs

**Non-Goals:**
- Shared conversations or state between instances
- Additional microvm or additional RAM
- Agenix-managed secrets (onboard wizard handles credentials)

## Decisions

### Mirror the existing service pattern with a `-janine` suffix

Create `openclaw-janine` system user, `openclaw-install-janine` and `openclaw-gateway-janine` systemd services. All follow the exact same pattern as the existing pim services but with different paths and port.

**Why:** Minimal new code — duplicate the service definitions with different variables. Both instances are fully independent and can be managed separately.

### Onboard wizard for configuration (no declarative config)

Like the pim instance, Janine's config is generated by running `openclaw onboard` inside the guest. The config JSON (including Matrix credentials) lives in the persistent state dir.

**Why:** The OpenClaw config schema is complex and poorly documented. The onboard wizard generates a valid config with correct plugin entries, auth profiles, and channel settings. We learned this the hard way with pim's instance.

### Wrapper scripts deployed via environment.systemPackages

Create two shell scripts (`openclaw-pim` and `openclaw-janine`) that set the correct env vars and call the openclaw binary. Deployed as NixOS packages via `pkgs.writeShellScriptBin`.

**Why:** Avoids remembering long env var chains when administering each instance. The scripts set `OPENCLAW_CONFIG_PATH`, `OPENCLAW_STATE_DIR`, `HOME`, and `PATH` correctly.

### Separate documents directory for Janine

Create `documents-janine/` alongside the existing `documents/` in the guest config directory. Contains a Dutch-language SOUL.md.

**Why:** Each instance needs its own personality. Janine's assistant should respond in Dutch by default.

## Risks / Trade-offs

[Risk] Both instances share the same OpenAI subscription OAuth token → Mitigation: OpenAI allows multiple sessions. Each instance runs `openclaw models auth login` independently. If token conflicts arise, we can investigate shared token state.

[Risk] Memory pressure with two instances (~500MB combined) → Mitigation: The VM has 2GB with ~900MB free after one instance. Sufficient headroom.

[Risk] npm install race condition if both install services run simultaneously → Mitigation: They use separate npm prefixes (`/var/lib/openclaw/.npm-global` vs `/var/lib/openclaw-janine/.npm-global`), so no conflict. Both can install in parallel.
