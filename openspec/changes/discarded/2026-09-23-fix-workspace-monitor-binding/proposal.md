## Why

Workspaces 1–7 are supposed to live on the external monitor
(`hyprland-monitor-topology`), but they frequently end up on the laptop panel
`eDP-1` instead — even though their number is in the 1–7 range. Investigation
(via `/opsx:explore mipnix-gfz4`) found the root cause is **two systems assigning
the workspace→monitor binding on different triggers, disagreeing on the target**:

1. **A hardcoded connector pin.** `modules/USERS/pim/programs/hyprland/hypr/workspaces.conf`
   pins `workspace=1..7,monitor:DP-3`. These become persistent Hyprland
   **workspace rules** (`hyprctl workspacerules` confirmed `ws 1–7 → DP-3`) that
   fire on every workspace **focus/create**. But the external monitor enumerates
   as `DP-2` (home) or `DP-3` (work) depending on the port/location — so `DP-3`
   is usually a **dead connector**. When a workspace rule targets a monitor that
   doesn't exist, Hyprland falls the workspace back to the focused monitor —
   typically `eDP-1`. Hence 1–7 land on the laptop.

2. **The reconciliation fires on the wrong events.** The
   `workspace-monitor-rehome` script computes the correct monitor dynamically
   ("first monitor that is not `eDP-1`" = the real external), but it only
   reconciles on `monitoradded`/`monitorremoved` and at startup. It does **not**
   react to workspace focus/create, so it cannot counter the stale `DP-3` rule
   when you simply switch workspaces without a hotplug. The rule wins; the
   workspace stays stranded until the next monitor event.

A false assumption in the current spec compounded this: `coexist-with-nwg-displays`
claims the runtime reconciliation "remains correct even after workspaces.conf is
regenerated by nwg-displays." In this home-manager/ricing setup, `workspaces.conf`
is an **immutable Nix-store symlink** built from the repo — nwg-displays cannot
rewrite it. The stale `DP-3` is not a moving target from a GUI tool; it is a
frozen mistake in the repo that is sourced on every start. And "remains correct"
was only ever true on monitor events, not workspace events.

A static config file fundamentally **cannot** name the external connector, because
it varies (`DP-2`/`DP-3`) — which is the whole reason the runtime script exists.
So the fix is to stop the static file from naming it at all, and let the runtime
script be the sole, correctly-triggered authority.

## What Changes

- **Remove the connector pins for workspaces 1–7** from `workspaces.conf`. Those
  workspaces get no `monitor:` rule; their placement is owned entirely by the
  runtime reconciliation. Keep `default:true` on workspace 1 (it is independent of
  the monitor pin). Keep the `monitor:eDP-1` pins on 8/9/0 — `eDP-1` is the laptop
  panel and is genuinely stable, so those are not lies.
- **Make the reconciliation fire on workspace events too.** Extend the
  `workspace-monitor-rehome` socket2 listener to also reconcile on workspace
  focus/create (and focused-monitor change), not only monitor add/remove, so a
  1–7 workspace is placed on the external monitor as soon as it appears/focuses —
  with a guard against self-triggered event loops.

## Capabilities

### Modified Capabilities

- `hyprland-monitor-topology`: strengthen `reconcile-on-hotplug-and-startup` to
  also reconcile on workspace focus/create events, and replace the (proven-false)
  `coexist-with-nwg-displays` assumption with the honest arrangement — the static
  config SHALL NOT pin a connector for the external workspaces; the runtime
  reconciliation is the sole owner of their binding.

## Impact

- `modules/USERS/pim/programs/hyprland/hypr/workspaces.conf`: drop
  `monitor:DP-3` from workspaces 1–7 (keep `default:true` on ws1; keep eDP-1 pins
  on 8/9/0).
- `modules/USERS/pim/programs/hyprland/scripts/workspace-monitor-rehome`: also
  match workspace/create/focusedmon socket2 events → reconcile; add a debounce /
  self-trigger guard so `moveworkspacetomonitor` doesn't cause an event loop; the
  header comment's "nwg-displays keeps rewriting workspaces.conf" note is
  corrected (the file is immutable/repo-owned).

## Out of Scope

- The literal "manual shortcut to bind workspace to other screen" from the bean
  `mipnix-gfz4`. That request was a symptom of the broken auto-binding; fixing the
  auto-binding is expected to remove the need. A deliberate ad-hoc "move this
  workspace to the other monitor (override policy until next reconcile)" shortcut
  can be proposed separately later if still wanted.
- The stray runtime `workspace 10` observed during exploration. No config
  references it (keybinds use `MOD+0` → workspace 0); it appears to be runtime
  cruft, not part of this fix.

## Notes

- Trade-off: with the connector pin gone, a 1–7 workspace may briefly appear on
  the focused (possibly laptop) monitor before the reconciliation moves it to the
  external monitor. Accepted; the alternative (a static pin) cannot be correct for
  a variable connector. The workspace-event trigger minimizes the window.
