## Context

Hyprland (0.55.2) is configured via plain `.conf` files delivered by Home Manager
(`home.file.".config/hypr".source = ./hypr`). Monitor geometry and workspace→monitor
bindings are generated by **nwg-displays** into `monitors.conf` and `workspaces.conf`
(marked "do not edit manually").

Observed live state at time of investigation:

```
eDP-1  2256x1504 @(4295,0) scale 1.33   (laptop)        — desc "BOE 0x095F"
DP-2   3840x2160 @(1735,0) scale 1.5     (external now)  — desc "LG ULTRAFINE ..."
DP-3   — not connected
```

Config pins workspaces 1–7 to `DP-3` and 8/9/0 to `eDP-1`, with `default:true` on both
ws1 (DP-3) and ws8 (eDP-1).

Key constraint discovered during exploration: the external monitor is a **different
physical monitor** at home vs. work, on a **different HDMI port**, so neither the
connector name (`DP-2`/`DP-3`) nor a fixed monitor description (`desc:`) is stable
across locations. The only stable distinction is "the one that is **not** the laptop
panel `eDP-1`."

## Goals / Non-Goals

**Goals:**
- Workspaces 1–7 always land on the connected external monitor, whatever its port/identity.
- Workspaces 8, 9, 0 stay on the laptop panel `eDP-1`.
- Default focus / new-window placement returns to the external monitor when present.
- Workspace 0 reachable by `MOD+0` is the same workspace mipbar previews (icons show).
- Keep nwg-displays as the geometry editor (user's choice).

**Non-Goals:**
- Multi-external-monitor layouts (user always has exactly one external at a time).
- Replacing nwg-displays or hand-managing `monitors.conf` geometry.
- Changing mipbar workspace-button code (already correct for id 0).
- Per-location (home/work) config files or profiles.

## Decisions

### Bug 1: Runtime hotplug listener, not static binding

Run a small script (in `hypr/scripts/`, launched via `exec-once`) that subscribes to
Hyprland's `socket2` event stream and, on `monitoradded`/`monitorremoved`, re-homes
workspaces 1–7 onto the first monitor whose name is not `eDP-1`, using
`hyprctl dispatch moveworkspacetomonitor <ws> <monitor>`. It also ensures 8/9/0 are on
`eDP-1`.

**Why**: The external monitor's connector name and description both vary by location, so
no static `workspace=N,monitor:...` line can be correct everywhere. "Not the laptop
panel" is the only stable predicate, and it can only be evaluated at runtime against the
live monitor list. A listener also handles hotplug (dock/undock) without relogin.

**Why this coexists with nwg-displays**: nwg keeps owning `monitors.conf` geometry and
the static `workspaces.conf`. Those static bindings are simply *overridden* at connect
time by the listener. Regenerating with nwg-displays cannot reintroduce the stranding
bug because the listener re-applies the correct binding on the next monitor event.

**Verified primitives** (Hyprland 0.55.2): `moveworkspacetomonitor <workspace> <monitor>`
dispatch exists; `socket2.sock` event stream is available; `hyprctl monitors -j` exposes
monitor names for the "non-eDP-1" selection.

**Alternatives considered**:
- *`monitor=desc:<LG ...>` + `workspace=N,monitor:desc:...`* — rejected: different
  physical monitors at each location, so a fixed description won't match both.
- *Per-monitor `defaultworkspace` in a catch-all `monitor=` rule* — partially viable, but
  fights nwg-displays ownership of `workspaces.conf` and is awkward for "any unnamed
  external monitor". The runtime listener is more robust and location-agnostic.
- *Static rename `DP-3`→`DP-2`* — rejected: just moves the breakage to the other location.

### Bug 1: "default focus" follows from correct binding

Once ws1–7 have a real home on the external monitor again, ws1 (`default:true`) is valid
on the external screen, so Hyprland's default focus / cursor home returns there. No
separate cursor-warp fix is needed; the stranding was the cause, cursor centering on the
laptop was the symptom.

### Bug 2: Unify on workspace id 0 (keep 0, fix mapping)

Retarget the keybinds so `MOD+0` → `workspace 0` and `MOD+SHIFT+0` → `movetoworkspace 0`
(currently both target `10`). `workspaces.conf` already declares `workspace=0` on `eDP-1`,
and the mipbar workspace button already queries id 0. Aligning the keybind closes the
three-way mismatch; windows sent with `MOD+SHIFT+0` then land on id 0, and mipbar shows
their icons.

**Why keep 0 rather than delete it**: user choice — workspace 0 lives on the laptop,
which the user uses. Deleting it and remapping to id 10 was the alternative.

**Alternative considered**: drop workspace 0 entirely and let key 0 map to workspace 10
(matching the current keybind). Rejected per user preference to keep a real ws0.

## Risks / Trade-offs

- **[Risk] Listener race on login** — monitors may already be connected before the
  listener starts. *Mitigation*: the script performs an initial reconciliation pass on
  startup (not only on events), then listens.
- **[Risk] nwg-displays regeneration confusion** — a future user editing layouts in nwg
  might expect `workspaces.conf` to be authoritative. *Mitigation*: document in the
  config that the runtime listener owns the workspace→monitor binding; nwg owns geometry.
- **[Risk] `eDP-1` name assumption** — hardcodes the laptop panel name. Stable for this
  hardware; if a future laptop panel enumerates differently, the predicate "not eDP-1"
  needs updating. *Mitigation*: match the laptop by `desc:` (BOE panel) is possible but
  `eDP-1` is conventionally stable; keep the name, document the assumption.
- **[Trade-off] Runtime vs. declarative** — a hotplug script is less "pure Nix" than a
  static binding, but it is the only correct solution given different external monitors
  per location. The script itself is delivered declaratively via the Nix-managed
  `hypr/scripts/` dir.
