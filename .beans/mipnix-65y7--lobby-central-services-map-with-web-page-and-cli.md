Briefing for building **lobby**: the first place to look when you want to
know where a service runs and how to reach it. Use this bean as the epic for
the OpenSpec proposal.

## Problem

Services run on several hosts (dapperehaan, durer, hurry, stinkie) and are
reachable in different ways: nebula only, LAN, public domain, or a
cloudflared tunnel. Finding "where is Immich again, and on which port" means
reading host files. There is no overview, and nothing keeps one up to date.

## What lobby is

One registry in the flake, filled where each service is configured, with two
consumers generated from it at build time:

```
 module that configures a service
   └─ flake.lobby.services.<name> = { ... }      (one entry, next to the config)
                     │
          lobby registry (flake level)
            ┌────────┴─────────┐
            ▼                  ▼
   web page on dapperehaan   `lobby` CLI on the global PATH
   http://lobby/             lobby, lobby open immich
   (nebula only)
```

## Decisions already made

- **Name:** lobby, for the whole system: registry, page and CLI.
- **Lives inside mipnix**, not in its own repository: a package under
  `packages/lobby` plus NixOS/home-manager modules. No extra flake input.
- **Registry pattern:** a flake-level option like `flake.nebulaNodes`,
  `flake.resticRepos` and `flake.syncthingDevices`
  (see `modules/services/networking/nebula-nodes-option.nix`): plain data,
  merged across modules, so consumers read it without evaluating any
  `nixosConfiguration` (avoids the evaluation cycle described in
  `modules/services/sync/syncthing-pool.nix`).
- **Registration is explicit**, one entry per service in the module that
  configures it. Deriving services from `services.*.enable` was rejected: it
  misses custom units (Backrest, hip-repo-backup) and cannot tell how a
  service is reached.
- **Source location is automatic:** record where each entry is defined with
  `builtins.unsafeGetAttrPos`, so lobby can show `grafana.nix:42` without
  anyone writing it down. Store it relative to the repository root.
- **Page hosted on dapperehaan**, nebula only, bound to `192.168.100.2`,
  like Grafana (`:3000`) and Backrest (`:9898`). dapperehaan is always on and
  already serves the nebula-only UIs.
- **Address `http://lobby/`:** add a `lobby` alias for dapperehaan's nebula
  IP to the `networking.extraHosts` entries that the nebula module already
  generates from `flake.nebulaNodes`, so every mesh member resolves it.
- **Page is a static HTML file generated by Nix**, served by nginx on
  dapperehaan. No dashboard application, no state. (homepage-dashboard in
  nixpkgs was considered; it can still be fed from the registry later.)
- **CLI is a separate command `lobby`** on the global PATH, not an `rme`
  subcommand. The registry is baked in at build time, so it works when
  dapperehaan is down.

## Registry entry (proposed schema)

```nix
flake.lobby.services.grafana = {
  description = "Dashboards for host health, backups, NixOS and piethein";
  host = "dapperehaan";
  url = "http://192.168.100.2:3000";
  access = "nebula";          # nebula | lan | public | tunnel | local
  category = "monitoring";    # free text, used for grouping
};
```

Where possible a module builds `url` from the same values it configures
(port, nebula IP from `flake.nebulaNodes`), so the URL cannot drift from the
configuration. `host` must be a key of `flake.nebulaNodes` or a known
non-mesh host (piethein). Entries without a web UI (Samba, Syncthing) may
set `url = null` and still appear in the list.

## CLI behaviour

- `lobby`: list all services grouped by category, with host, access and URL.
  On a TTY, offer a fuzzy picker (gum is already used in mipnix) and open the
  choice.
- `lobby open <name>`: open the URL with `xdg-open` (or `open` on macOS).
- `lobby show <name>`: all fields, including the source location.
- `lobby --json`: the registry as JSON, for scripts.
- Exit non-zero with a clear message for an unknown name; suggest close
  matches.

Language is open: a shell script with jq over a generated JSON file is
enough for a first version.

## Web page

- One static page: services grouped by category, each as a link, with host,
  access type, description and source location.
- Readable at phone width, light and dark mode.
- Served at `http://lobby/` on dapperehaan's nebula IP only.

## Out of scope for the first version

- Up/down status per service. Later: a Prometheus blackbox exporter that
  checks every URL in the registry, shown on the page and in Grafana.
- Authentication on the page; nebula membership is the access control.
- Feeding Uptime Kuma from the registry.

## Done when

- `http://lobby/` from any mesh member lists every service above.
- `lobby` lists them in a terminal and `lobby open grafana` opens Grafana.
- Adding a service means adding one registry entry in its own module; page
  and CLI pick it up on the next build.
- Each entry shows the file and line where it is registered.
